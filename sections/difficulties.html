Difficulties & solutions

The traps that cost us (and other teams) the most time — and exactly how we got past them.

A motor spun the wrong way

Found during the channel test. Fix: swap any two of the three ESC-to-motor wires — which meant unscrewing the arm and disconnecting the LED.

Pitch felt inverted

Right stick forward → drone backwards. Fix: invert the pitch channel on the transmitter.

Odd autopilot behaviour after flashing

Leftover parameters from previous users. Fix: reset all parameters to default right after flashing firmware, then re-apply ours.

US vs EU stick mode

Default stick mapping differed from what we expected. Fix: verify and set the stick mode before building the model (Fig 4.6).

Telemetry link slower than USB

Expected behaviour, not a fault. Approach: use USB for heavy config, telemetry radio for in-field checks and flight.

Our own difficulties.

Motor/ESC inconsistency.

During individual motor testing, one motor produced a noticeably different sound from the other three. Its response to the minimum throttle threshold was also different: we had to increase the test threshold for the motor to start normally. After replacing the motor, the same behavior appeared again, so we currently suspect that the issue may be related to the ESC rather than the motor itself. Interestingly, the difference did not appear to affect the UAV's normal flight performance during the flight test. One possible explanation is that the flight controller automatically compensates for small differences in motor output, although this still needs further investigation.

Missing Parameters When Loading the Param File

When loading the recommended parameter file, Mission Planner reported that some parameters were missing or could not be recognized. Fix: We checked the latest parameter names and their corresponding units, updated the configuration file accordingly, and then loaded the modified file again.
